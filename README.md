# model-thinking · 模型思考法

> 把万维钢《颗粒度和因果中介：用模型思考》做成一个可执行的技能。
> **一句话：别盯终点，盯中介。**

[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](./LICENSE)

---

## 解决什么问题

**面对一件复杂的事，不知道从哪下手。**

- 有一堆指标/选项，不知道该盯哪个 → **多半是过拟合**
- 凭直觉在反应，说不清为什么 → **多半是欠拟合**
- 想改一件事，改了半天没效果 → **多半改错了变量**
- 别人给你一句「因为A所以B」，你怀疑它太糙 → **多半少了中介**

**这个技能给你一套三步走的动作**，把「凭感觉」换成「有模型、有因果、有控制点」。

---

## 主要功能

| 能力 | 说明 |
|---|---|
| **建模** | 逼你把终点和因果链写清楚；用**可干预原则**区分因果与相关 |
| **定颗粒度** | 用**最小描述长度（MDL）**判你现在的模型是欠拟合还是过拟合，该加变量还是该砍 |
| **找中介** | 从因果链里挑出 **1–2 个能直接干预、又能改变结果**的关键变量 |
| **批判性提醒** | 5 条常见误用（把相关当因果、模型太漂亮、忘了终点、一次找太多中介、以为模型等于现实） |

**内置 5 组完整案例**：生气与癌症 ·《点球成金》上垒 · 足球期望威胁 xT · 孩子学习 · 公司管理。

## 使用方法

**触发方式**：直接问就行。这个技能在下面这些场景会被命中——

> 「我该怎么下手」「这事儿的控制点在哪」「我是不是想复杂了 / 想简单了」
> 「该盯哪个指标」「为什么改了没效果」「别盯终点盯中介」

**或者显式调用**：

```
用模型思考法分析一下：<你的事>
```

**它会照这个结构答：**

```
① 终点：你要控制的那个结果是什么？（一句话）
② 现在用的模型：说清楚它是什么（哪怕它是错的）
③ 诊断：欠拟合还是过拟合？为什么？
④ 新模型：写成因果箭头   A → B → C → 终点
⑤ 关键中介：1–2 个，说清为什么是它（可干预 + 能改变结果）
⑥ 下一步动作：对中介动手，具体做什么
```

## 输入输出示例

**输入：**

```
用模型思考法分析一下：我的内容站，怎么才能让更多人看到？
```

**输出（节选）：**

```
① 终点：更多人「读到并留下」——不是更多人「刷到」。

② 现在用的模型（错的）：内容好 → 更多人看到。
   这是把「好」当成了因，但「好」不是一个能动手的变量。

③ 诊断：欠拟合。模型太短，丢掉了「人怎么找到你」这一整段。

④ 新模型：
   （真实搜索词 + 内容质量）→ 被搜到 → 被读到 → 被信任 → 留下来

⑤ 关键中介：真实搜索词。
   为什么是它 ——
   · 可干预：你能改标题、改关键词、改选题
   · 能改变结果：别人都在盯「内容质量」（终点旁边那个），
     没人盯「别人会不会打这个字去搜」——这里没有被定价

⑥ 下一步：把「我这个选题，用户会打哪几个字」变成写稿前的第一道工序。
```

## 已知限制

- **不是决策替代品。** 它逼你把因果关系写清楚，**写出来的箭头对不对仍然是你的责任**。
- **颗粒度没有绝对标准。** 原文明确说「细致到什么程度，由你的主观需求决定」——本技能只能给你判断的**判据**，不能替你定。
- **`references/wangweigang-original.md` 是提取版，不是逐字全文。** 逐字全文在得到 App 里（精英日课）。
- **不含任何 API 调用或脚本。** 纯方法论 + 输出模板。
